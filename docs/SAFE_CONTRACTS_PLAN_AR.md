# SafeContracts — وثيقة الخطة الوظيفية والتنفيذية

**الإصدار المرجعي:** V1.2  
**اسم النظام:** SafeContracts  
**الباك إند:** WordPress Custom Plugin  
**التطبيق:** Mobile Application  

## 1. هدف النظام

SafeContracts هو نظام لمتابعة عقود شركة إعلانات مع جهات وعملاء مختلفين، والتركيز الأساسي على **الدفعات المالية المستحقة للشركة طبقًا للعقود**، ومواعيد استحقاقها، وحالات التحصيل والمتابعة بواسطة المحاسبين والمديرين.

الهدف الأساسي هو منع نسيان أو تأخر متابعة أي دفعة، وإعطاء الإدارة رؤية واضحة لحالة العقود والمستحقات والمتأخرات والتحصيلات.

الافتراضي أن يتم التنبيه قبل موعد استحقاق الدفعة بـ **10 أيام** للمحاسب المسؤول والمدير، مع وجود منصة إعدادات كاملة لإدارة قواعد التنبيهات.

## 2. المعمارية العامة

WordPress مع Plugin مخصص لـSafeContracts هو **المصدر الوحيد للحقيقة Single Source of Truth**.

الـPlugin مسؤول عن:

- إنشاء وترقية جداول قاعدة البيانات الخاصة بالنظام.
- العملاء والجهات.
- العقود.
- بنود العقود المالية والإضافات والخصومات.
- جداول الدفعات ومواعيدها.
- عمليات التحصيل.
- طرق السداد.
- المتابعات والملاحظات.
- المستخدمين والصلاحيات ونطاق البيانات.
- التنبيهات وقواعدها.
- إعدادات Firebase والـPush Notifications.
- إعدادات تطبيق الموبايل والبيانات القابلة للتغيير فيه.
- التقارير وتصدير Excel.
- سجل التدقيق Audit Log.
- استيراد Excel.
- REST API التي يستخدمها تطبيق الموبايل.

تطبيق الموبايل لا يملك Backend مستقلًا ولا Business Logic ينافس WordPress. كل البيانات المرجعية والصلاحيات والحالات والإعدادات تأتي من WordPress.

## 3. أنواع المستخدمين والصلاحيات

### مسؤول النظام System Administrator

يمتلك إعدادات النظام الكاملة، المستخدمين، الصلاحيات، الهوية البصرية، Firebase، قواعد التنبيهات، طرق السداد، الاستيراد والإعدادات الفنية.

### المدير Manager

يرى جميع العملاء والعقود والدفعات والتحصيلات والمتابعات، ويمكنه استخدام الفلاتر على كامل البيانات. يستطيع التعديل في الحدود التي تمنحها له الـCapabilities.

### المحاسب Accountant

إضافة العقود من أساس عمل المحاسب. كل محاسب يرى فقط العقود والدفعات المسندة إليه. يستطيع تنفيذ أعمال المتابعة والتحديث والتحصيل في حدود الصلاحيات الممنوحة له.

### المشاهد Viewer

صلاحية قراءة فقط داخل نطاق البيانات المسموح به.

### قاعدة تعديل العقود

تعديل العقود ليس مقصورًا على Role ثابت. يتم تنفيذه كـCapability يمكن منحها أو سحبها من أي Role حسب إعدادات النظام.

إخفاء قائمة أو زر داخل WordPress لا يعتبر حماية أمنية؛ كل صلاحية ونطاق بيانات يجب تطبيقه فعليًا على السيرفر والـAPI.

## 4. إدارة العملاء والجهات

يحتوي العميل/الجهة على البيانات الأساسية ووسائل الاتصال والملاحظات، مع وجود **كود داخلي اختياري** وليس إلزاميًا.

الوظائف:

- إضافة عميل.
- تعديل بيانات العميل.
- أرشفة/تعطيل العميل حسب السياسة.
- كود داخلي اختياري.
- البحث والفلترة.
- عرض عقود العميل.
- عرض ملخص المستحقات والتحصيلات الخاصة به.

## 5. إدارة العقود

كل عقد مرتبط بعميل/جهة ويتم إسناده إلى محاسب مسؤول.

بيانات ووظائف العقد تشمل:

- رقم/مرجع العقد.
- العميل.
- المحاسب المسؤول.
- تاريخ البداية والنهاية.
- حالة العقد.
- القيمة الأساسية.
- عملة واحدة للنظام.
- بنود مالية.
- إضافات.
- خصومات.
- صافي قيمة العقد.
- ملاحظات.
- مرفقات.
- تاريخ التغييرات.

يمكن تعديل Due Date أو أي بيانات أخرى بواسطة مستخدم لديه الصلاحية المناسبة، ويجب تسجيل التغيير في Audit Log عند كونه تغييرًا جوهريًا.

قيمة العقد لا يلزم أن تكون مجرد مجموع بسيط للدفعات لأن العقد قد يحتوي على بنود أو إضافات أو خصومات منفصلة. يجب أن يعرض النظام تسوية مالية واضحة.

## 6. جدول الدفعات المستحقة

كل عقد يحتوي على دفعة واحدة أو أكثر طبقًا للاتفاق.

كل دفعة تحتوي على:

- رقم/ترتيب الدفعة.
- العقد المرتبط.
- تاريخ الاستحقاق الأصلي.
- تاريخ الدفع المتوقع إذا تغير خلال المتابعة.
- قيمة الدفعة.
- المبلغ المحصل.
- المبلغ المتبقي.
- الحالة المالية.
- المتابعات والملاحظات.
- عمليات التحصيل.
- حالة التنبيهات.
- سجل التغييرات.

الحالات المالية المقترحة:

- Upcoming — قادمة.
- Due Soon — اقترب موعدها.
- Due — مستحقة.
- Overdue — متأخرة.
- Partially Paid — محصلة جزئيًا.
- Paid — محصلة بالكامل.

يمكن وجود حالة متابعة تشغيلية منفصلة مثل تم التواصل، وعد بالسداد، توجد مشكلة، مؤجلة؛ دون إفساد الحالة المالية الفعلية للدفعة.

## 7. عمليات التحصيل

يمكن تحصيل الدفعة دفعة واحدة أو على أجزاء.

كل عملية تحصيل تحتوي على:

- المبلغ.
- تاريخ التحصيل.
- **طريقة السداد إلزامية**.
- رقم مرجعي/بيانات العملية إن وجدت.
- مرفق إثبات اختياري.
- المستخدم الذي سجل التحصيل.
- تاريخ الإنشاء والتعديل.

المرفق غير إلزامي، لكن طريقة السداد إلزامية.

## 8. طرق السداد

طرق السداد موجودة في جدول قابل للإدارة من WordPress ولا تكون Hard-coded في تطبيق الموبايل.

القيم المبدئية:

- نقدًا Cash.
- تحويل بنكي Bank Transfer.
- محفظة Wallet.

يستطيع مسؤول النظام إضافة طريقة جديدة، تعديل الاسم، الترتيب، التفعيل أو التعطيل. تطبيق الموبايل يحصل على القائمة النشطة من API.

## 9. نظام التنبيهات

داخل WordPress توجد منصة إعدادات متكاملة لقواعد التنبيه.

القاعدة الافتراضية:

**إرسال تنبيه قبل استحقاق الدفعة بـ10 أيام إلى المحاسب المسؤول + المدير.**

لكن يستطيع مسؤول النظام التحكم في:

- عدد الأيام قبل الاستحقاق.
- تنبيه يوم الاستحقاق.
- تنبيهات بعد التأخير.
- التكرار.
- التصعيد.
- الأدوار المستقبلة.
- المحاسب المسند إليه العقد.
- القنوات المستخدمة.
- تفعيل/تعطيل كل Rule.
- قالب الرسالة.

يجب ألا يستمر إرسال تنبيه غير مناسب بعد سداد الدفعة بالكامل.

## 10. Firebase وPush Notifications

إعدادات Firebase تتم من داخل SafeContracts في WordPress.

تشمل:

- إعدادات المشروع المطلوبة.
- تسجيل Device Tokens.
- تحديث/إلغاء Tokens.
- توجيه Push حسب المستخدم/الدور والنطاق.
- قوالب الرسائل.
- سجل الإرسال.
- حالات الفشل وإعادة المحاولة.

لا يتم إرسال الأسرار إلى تطبيق الموبايل إلا بالقدر الآمن والضروري تقنيًا.

## 11. لوحة إدارة WordPress والـWhite Label

الـPlugin لا يظهر كصفحات إضافية داخل WordPress التقليدي فقط، بل يعيد تشكيل تجربة الإدارة التشغيلية بالكامل تحت هوية **SafeContracts**.

يشمل ذلك:

- شعار واسم SafeContracts.
- شاشة Login بهوية النظام.
- ألوان النظام.
- Header وFooter.
- قائمة جانبية مبسطة.
- Dashboard خاصة بالنظام بدل Widgets ووردبريس الافتراضية.
- إخفاء القوائم غير المطلوبة للمستخدمين التشغيليين مثل Posts وComments وAppearance وPlugins وTools وغيرها حسب الدور.
- الاحتفاظ بالإعدادات الفنية اللازمة لمسؤول النظام.

القوائم التشغيلية الرئيسية:

- Dashboard.
- Customers.
- Contracts.
- Payments.
- Collections.
- Follow-up.
- Notifications.
- Reports.
- Users & Permissions عند السماح.
- SafeContracts Settings.

الـWhite Label لا يلغي طبقات حماية WordPress؛ الوصول الفعلي يتم بالـCapabilities.

## 13. Dashboard الموبايل والفلاتر

الـDashboard يظهر البيانات طبقًا لصلاحية المستخدم ونطاقه.

آلية الفلترة:

1. Dropdown لاختيار العميل.
2. بعد اختيار العميل يتم تحميل عقوده المتاحة للمستخدم في Dropdown ثانية.
3. يمكن اختيار All Contracts أو عقد معين.
4. يتم تحديث الـKPIs والقوائم والمستحقات والمتأخرات طبقًا للفلاتر المختارة.

المحاسب لا يرى إلا عقوده حتى لو حاول تغيير قيمة الفلتر يدويًا؛ التحقق يتم على السيرفر.

المدير يرى جميع العقود ويمكنه الفلترة.

## 14. تصدير Excel من الموبايل

يوجد زر Export Excel في Dashboard الموبايل.

التصدير يطابق نفس:

- العميل المختار.
- العقد المختار أو All Contracts.
- نطاق التاريخ والحالة إذا كانا مطبقين.
- صلاحيات ونطاق المستخدم.

ملف Excel يتم إنشاؤه في WordPress Backend، والموبايل يطلبه وينزله/يشاركه. لا يقوم الموبايل ببناء تقرير مالي مستقل محليًا.

يتم تسجيل عملية التصدير في Audit عند الحاجة.

## 16. Audit Log

يتم تسجيل التغييرات المهمة، ومنها:

- إنشاء وتعديل العقد.
- تغير حالة أو تاريخ أو قيمة العقد.
- تغير الدفعات وقيمها وتواريخها وحالاتها.
- عمليات التحصيل والتعديل/الإلغاء حسب السياسة.
- تغيير المحاسب المسؤول.
- تغيير الصلاحيات.
- إعدادات التنبيهات.
- عمليات Import وExport المهمة.

السجل يحتوي على المستخدم والوقت والكيان ونوع العملية والقيم قبل/بعد عند الحاجة.

## 18. إعدادات الموبايل الديناميكية

من WordPress يمكن إدارة البيانات المناسبة التي تظهر في التطبيق، مثل:

- اسم النظام.
- Logo.
- الألوان المدعومة.
- Header/Footer text.
- بيانات الدعم.
- بعض النصوص والقيم المرجعية.
- Feature Flags المحددة.
- إعدادات التنبيهات.

لكن Layout الأساسي والأمان والسلوكيات الحرجة تظل جزءًا من كود التطبيق ولا يسمح بإرسال UI عشوائي غير آمن من السيرفر.

- Customers.
- Contracts.
- Contract Financial Items.
- Scheduled Payments.

- Payment Methods.
- Follow-ups.
