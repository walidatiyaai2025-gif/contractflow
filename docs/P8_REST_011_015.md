# P8 REST API — SC-P8-011..015

This slice implements five mobile-facing SafeContracts REST capabilities without duplicating business rules already owned by the WordPress backend.

## Endpoints

- `GET /safecontracts/v1/dashboard` — server-scoped KPI/filter bootstrap using `AdminReadRepository` and `DashboardFilters`.
- `GET /safecontracts/v1/mobile-config` — non-secret mobile bootstrap values from `MobileConfiguration`.
- `GET /safecontracts/v1/reference-data` — active payment methods projected to mobile-safe fields.
- `GET /safecontracts/v1/reports/excel` — authenticated XLSX download payload generated by `ReportExportService`.

All endpoints require SafeContracts access. Dashboard additionally requires `VIEW_ALL` or `VIEW_ASSIGNED`; Excel requires `EXPORT_REPORTS`, which remains distinct from `VIEW_REPORTS`.

## Validation / error boundary

`SafeContracts\Rest\RequestGuard` centralizes request parameter extraction, dashboard filter normalization, stable `WP_Error` status codes and safe internal-failure messages. Raw exception, SQL or secret detail is never returned for unexpected failures.

## Security and data ownership

- REST controllers contain no direct `$wpdb` access.
- Dashboard/accountant scope remains enforced inside existing backend read models.
- Contractual `due_date` remains the authoritative source for overdue dashboard calculations.
- Mobile configuration exposes only normalized non-secret values and explicit feature flags.
- Reference data exposes only active payment method `id`, `code`, `name`, and `display_order`.
- Excel generation remains inside `ReportExportService`, retaining server-side filters, formula-injection protection and export audit evidence.
- XLSX bytes are transported as base64 with filename/MIME metadata so the mobile client can materialize a local file without reconstructing authoritative report data.

## Regression coverage

`tests/php/rest_api_011_015.php` covers route registration, malformed filter fail-closed behavior, assigned-accountant scope, mobile config secret isolation, safe reference-data projection, export-capability separation, real XLSX ZIP output, audit evidence and no direct SQL in REST controllers.
