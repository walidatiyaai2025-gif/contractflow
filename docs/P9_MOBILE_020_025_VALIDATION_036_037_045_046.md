# P9 mobile operations — SC-P9-020..025 + validation SC-P9-036/037/045/046

This slice completes six remaining non-overlapping mobile implementation workstreams while the team owns SC-P9-013..019, and adds four validation tasks around already-delivered Contracts plus the new notification/deep-link boundary.

## SC-P9-020 — Notifications inbox — Implement

- Adds protected `GET /safecontracts/v1/notifications` with bounded page 1..5 and page size 1..50.
- The server query is pinned to `get_current_user_id()` and sent deliveries only.
- Mobile projection excludes device-token IDs, transport responses, error codes and user IDs.
- Read/unread is persisted per WordPress user in bounded user-meta; Firebase remains delivery transport only.
- `POST /notifications/{id}/read` verifies the sent delivery belongs to the current user before persisting read state.
- Flutter supports lazy load, refresh, bounded paging, empty/error/offline states, New/Read presentation and safe deep-link handoff.

## SC-P9-021 — Push deep links — Implement

- Introduces a fail-closed resolver that accepts only known internal destinations (`payments`, `contracts`, `customers`, `followups`) plus a positive resource ID.
- Extra metadata, external URLs, unknown destinations and malformed IDs are rejected.
- Notification payload deep links must match the notification's authorized payment ID.
- The shell checks the current navigation policy before acting on a resolved deep link; push metadata never grants authorization.

## SC-P9-022 — Profile/session/device screen — Implement

- Adds protected `GET /safecontracts/v1/devices`, pinned to the current user.
- Server projection excludes raw Firebase token and token hash material.
- Profile shows safe session scope, granted SafeContracts capabilities, configured page size/support text and registered device operational state.
- Device models accept only positive IDs and known `android`/`ios`/`web` platforms.

## SC-P9-023 — RTL/responsive mobile UX — Implement

- Adds explicit Arabic RTL / non-Arabic LTR direction scope.
- Adds deterministic narrow/medium/wide breakpoints at 600 and 1024 logical pixels.
- Adds a bounded adaptive body primitive used by new operations screens.

## SC-P9-024 — Offline/error/loading states — Implement

- Adds reusable loading, empty, error, offline and forbidden state UI.
- Adds deterministic failure classification for 401, 403, validation errors, transport failures and invalid payloads.
- Notifications/profile use the shared states and retry actions.

## SC-P9-025 — Mobile test automation — Implement

- Adds `mobile/test/support/safecontracts_test_harness.dart`, a hermetic API harness backed by the existing fake transport and local SafeContracts environment.
- The harness covers API/session/config/navigation/deep-link/state tests without real network access or credentials.
- Existing Quality Gates already run `flutter test`, so every committed `_test.dart` using the harness is automatically enforced.

## SC-P9-036 — Contracts list — Validate

- Contract list IDs must be unique; list scope metadata is limited to `all`/`assigned`.
- Filter inputs remain allowlisted, but server-returned contract status stays opaque and authoritative.
- Contract dates are real ISO dates and money is retained as exact server strings; Flutter does not reinterpret numeric money.
- Invalid filters fail before transport access and stale list content is cleared while a new scoped request is loading.

## SC-P9-037 — Contract details — Validate

- Invalid local IDs fail before direct-object network access.
- Detail reads preserve exact server status/base value and map 403/404 distinctly.
- Detail authorization always comes from a fresh protected REST request; list visibility never grants direct-object access.

## SC-P9-045 — Notifications inbox — Validate

- Invalid paging fails before a database read.
- Duplicate notification IDs, invalid scope metadata and mismatched deep links fail closed.
- Mark-read verifies both notification ID and current user and returns 404 for an out-of-scope notification.
- Read-state persistence is bounded and per-user; delivery/internal fields never enter the mobile projection.

## SC-P9-046 — Push deep links — Validate

- Regression coverage rejects external URL destinations, unknown routes, zero/invalid IDs and payloads containing extra URL metadata.
- Resolver output is navigation intent only and remains subordinate to session capability/scope policy.
