# P9 Mobile Excel export — SC-P9-009

## Implemented slice

SC-P9-009 replaces the authorized **Excel export** navigation placeholder with a server-backed export flow that preserves WordPress as the financial reporting authority.

### Server-authoritative filters and workbook

- Mobile reuses the current `DashboardFilters` object and sends its `customer_id`, `contract_id`, `status`, `due_from` and `due_to` values to `GET /safecontracts/v1/reports/excel`.
- Flutter does not rebuild financial rows, totals, reconciliation logic or spreadsheet content locally.
- The existing WordPress endpoint remains responsible for capability checks, Accountant scope enforcement, normalized filters, workbook generation and export audit hooks.

### Capability-aware execution

- The export destination is still exposed only when the server session grants both report-view and report-export capabilities and the mobile `excel_export` feature flag is enabled.
- `MobileExcelExportController` receives that resolved authorization decision and refuses direct execution when export is not allowed, so hiding navigation is not the only client-side guard.
- WordPress remains the final authorization boundary on every export request.

### Download integrity and storage

- The client accepts only the expected XLSX MIME type and `base64` encoding returned by the REST endpoint.
- Decoded payloads must carry the ZIP/XLSX signature before they are written.
- Server filenames are reduced to a safe basename, restricted to a conservative filename character set and required to end in `.xlsx`, preventing a response filename from escaping the app export cache path.
- The downloaded server-generated bytes are saved to the application temporary/cache area through an injectable `ExcelExportSaver` boundary. Platform share/open integration can build on the saved path without changing financial-report semantics.

### UX states

The dedicated export screen shows:

- the current dashboard filter snapshot;
- disabled state when the session is not export-authorized;
- progress while the server workbook is being generated/downloaded;
- server/API or validation errors;
- success with filename, saved path, file size and server-provided row counts.

## Validation

`mobile/test/mobile_excel_export_009_test.dart` covers:

- exact propagation of the active dashboard filters to `/reports/excel`;
- successful Base64 XLSX decoding and save handoff;
- no network request when export capability is unavailable;
- filename/path traversal normalization;
- rejection of arbitrary non-XLSX payloads.

No credentials, tokens, Firebase secrets or independent financial calculations are introduced by this slice.
