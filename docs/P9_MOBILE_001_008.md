# P9 Mobile core — SC-P9-001..008

## Implemented slice

This slice turns the P0 Flutter foundation into the first server-backed SafeContracts mobile runtime while preserving WordPress as the sole business-data authority.

### SC-P9-001 — App architecture & API client

- `SafeContractsApiClient` owns the `/safecontracts/v1` envelope contract.
- `SafeContractsTransport` is injectable for deterministic tests.
- `IoApiTransport` uses bounded connection/request timeouts and a 2 MiB response ceiling.
- API base URL remains supplied by `AppEnvironment`; production requires HTTPS.
- No contract/payment/financial calculations are moved into Flutter.

### SC-P9-002 — Authentication/session

- Mobile bootstraps the protected `/session` endpoint and models authenticated, unauthenticated, forbidden and error states.
- Returned user ID, data scope and capability map drive the client experience.
- Session reset clears only in-memory SafeContracts session state.
- This slice does **not** invent an Application Password, password store, OAuth flow or Firebase credential flow. Authentication headers are an injected transport boundary so an approved credential-acquisition mechanism can be added without embedding passwords/server secrets in source.

### SC-P9-003 — Dynamic configuration bootstrap

- `/mobile-config` is parsed into typed support text, page size and feature flags.
- Unknown fields are ignored.
- Server page sizes are capped to the REST V1 `per_page <= 100` transport contract.
- If remote config fails, non-secret defaults are used and the shell visibly reports fallback mode.

### SC-P9-004 — Role-aware navigation

Navigation is derived from server-returned capabilities and data scope, never from hardcoded role names. Export and operational action availability also respect mobile feature flags.

### SC-P9-005 — Dashboard KPIs

The dashboard renders server-provided contract count and exact financial strings (`scheduled_total`, `remaining_total`, `overdue_exposure`, `collected_total`). Flutter does not recompute receivable totals.

### SC-P9-006 — Customer dropdown

The dashboard exposes an explicit client-side **All customers** option while customer records themselves remain server-authorized.

### SC-P9-007 — Dependent contract dropdown

Changing customer clears any stale contract selection and reloads `/filters/contracts?customer_id=...`. The explicit **All contracts** option never creates or widens server scope.

### SC-P9-008 — Dashboard filtered lists

The mobile repository loads contracts, payments, collections and follow-up rows using the current authorized filters plus the P8 bounded sort/pagination contract. Loading, empty, refresh and error states remain separate from the server's business semantics.

## Validation

- `mobile/test/mobile_core_001_008_test.dart` covers transport/envelopes, session states, config parsing, capability navigation, exact KPI values, dependent dropdown reset and filter propagation.
- `mobile/test/app_test.dart` exercises the authenticated bootstrap through the dashboard shell using a fake transport.
- Existing `app_environment_test.dart` remains part of the Flutter Quality Gates.
- No real credentials, passwords, access tokens, Firebase private keys or service-account JSON are committed.
