# P8 REST pagination & abuse hardening — SC-P8-016..017

## SC-P8-016 — Pagination/filter/sort

SafeContracts list endpoints now expose a deterministic bounded list contract on top of the existing server-authorized read models.

- Read window remains capped at 500 records.
- `page` remains 1..5 and `per_page` remains 1..100.
- Each endpoint has an explicit filter allow-list and sort allow-list.
- `order` accepts only `asc` or `desc`.
- Sorting is deterministic with an ID/payment-ID tie-breaker.
- Sorting happens only after backend scope/filter enforcement; it cannot widen `VIEW_ALL` / `VIEW_ASSIGNED` scope.
- Response metadata reports `page`, `per_page`, effective `sort`/`order`, bounded-window size and `has_more`.

Supported list defaults:

- customers: `name asc`
- contracts: `id desc`
- payments: `due_date asc`
- collections: `collection_date desc`
- follow-up queue: `due_date asc`
- follow-up history: `created_at desc`

## SC-P8-017 — API abuse/security hardening

The REST query boundary now fails closed before business reads when requests contain:

- unknown parameters,
- array/object parameter pollution,
- boolean type-confusion values,
- more than 12 top-level request parameters,
- scalar strings larger than 256 bytes,
- unsupported sort fields or sort directions,
- endpoint-irrelevant filters.

The hardening layer contains no direct SQL and does not replace WordPress authentication, SafeContracts capabilities or server-side accountant scope. Existing client-safe field projections and generic internal-error handling remain unchanged.

## Regression evidence

`tests/php/rest_api_016_017.php` validates bounded pagination, deterministic sorting, endpoint-specific query allow-lists, type-confusion/parameter-pollution rejection, read-only routes, safe projections and presentation-layer SQL separation. The suite is executed by `scripts/test-php.sh` and therefore by the repository Quality Gates workflow.
